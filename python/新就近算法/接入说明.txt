就近接入：当前原动作段优先版，2026-10-29

1. 本版规则与调用参数
没有增加上位机必传参数，models/settings及原曲线结构保持不变。
nearest_start=true、use_specified_time=false且提供stopped_time_ms时：
先在停止参考帧所属的整个原动作段中，按当前位置找可执行的最近接入帧。
当前段内允许查参考帧两侧。当前段有方案即使用，即使其他段更近/更快也不比较。
当前段最接近的一个点不可执行时继续查本段，不直接跳段；整窗全不可执行才按方向继续。
正向依次后续原段，反向依次前序原段，不跨全动作首末循环回另一端。
‘找不到’指整段无满足行程、限速及准备运动约束的可执行点，不是要求位置误差为0。

stopped_time_ms记录点击停止时的原曲线帧；runtime.models传停稳后的真实位置与速度。
因减速和惯性，实际位置可能对应本段参考帧另一侧，不能把参考帧继续用作硬搜索边界。
反向只决定接入后的曲线运行方向、同代价顺序及失败后查前序段，不代表当前段只能查小于参考的帧。

2. 上位机现有三个字段的对应关系
nearest=true -> command.nearest_start=true、command.use_specified_time=false。
reverse=true -> command.reverse=true（低层direction=-1，不是2）。
referenceFrameMs -> command.stopped_time_ms。
当前位置 -> runtime.models[].position_HPY；模型通过model_id/设备路由关联。
同一次传整个动作参与的全部模型，不按PLC分别求公共时间。

3. 什么是一段
顶层models[].segments中的原动作段，不是coefficient_segments的加速/匀速/减速小阶段。
归一化内部保留_entry_boundaries_ms，移植时也必须保留原段边界，不能只复制flatten后的系数。
多模型分段不一致时，将有运动模型的原段边界合成公共时间单元，所有模型共选一个帧。
整条曲线严格恒定的模型不切碎运动模型窗口，但仍参加准备计算和共同等待。
模型首末保持、空档保持纳入窗口；强制不同模型周期按现有循环映射懒计算，不全展开循环数。
参考恰好落在边界时：正向归右段、反向归左段；首末钳位到可用段。
这是按本次请求方向的明确默认归属，不推断停止之前的历史方向。

4. 本次问题的示例
示意曲线100@0ms -> 1000@10000ms -> 0@20000ms，两段线性。
停止参考12500ms，停稳位置534.98，当前原段为[10000,20000]。
reverse=true也先查整段，选14650ms附近的535位置，不再跳回前半段4850ms附近。
接回14650ms后才按反向向较小原曲线帧运行。
实际帧以原abcdef系数计算，不把示意14650硬编码。

5. 其他模式保持
use_specified_time=true：固定接入specified_time_ms，指定帧优先，不做段优先搜索。
use_specified_time=false且nearest_start=false：正向动作首帧、反向末帧。
就近但stopped_time_ms=null：保留没有历史参考的全动作就近规则；0仍是有效参考帧。
nearest_start并不替代use_specified_time；你们自定义nearest=false若表示‘指定帧’，要映射到指定标志。

6. 调用和结果
    from 就近接入计算 import calculate_nearest_entry
    result = calculate_nearest_entry(parameters)
直接传字典即可，不要求使用JSON文件；API不修改输入。
F5/CLI：python 就近接入计算.py
显式文件：python 就近接入计算.py 算法参数.json
新公共文件只更新nearest_result；旧就近接入参数.json保留独立结果文件兼容。

只有status=planned才能使用本次结果，infeasible或异常不能沿用上次结果。
selected_curve_time_ms是最后选中帧；prepare_time_ms是共同准备耗时，二者不同。
reference_segment_range_ms说明先查哪段；selected_segment_range_ms/search_range_ms说明最终哪段。
segment_search_phase为current_segment或directional_fallback，segment_search_attempts列实际尝试过程。
不要用targetFrameMs与referenceFrameMs大小关系判断是否nearest；新规则反向也可以target>reference。

强制：使用1006_payloads的公共帧、共同准备时长、设备V/A，按现场PLC描述文件编码。
1007仍使用共同T0释放准备，各PLC等待共同截止及本机准备完成。
非强制：完整执行axis_plans.move_steps和continuation_axis_moves，不能只取第一条Move。
准备下发时刻=T0+start_offset_ms；接续=T0+prepare_time_ms+start_offset_after_join_ms。
带速交接move_target可不同于join_position，不能等旧Move Done才覆盖。
can_dispatch=false仍表示旧1006/1007无法直接表达非强制带速轴队列，不能硬套。

7. 移植必须同步的流程
保留新增_entry_prioritized_windows；有停止参考时先取当前原段窗，成功才返回。
强制选择器的search_window_ms/frame_validator是内部参数；只让实际可执行候选收紧搜索上界。
非强制对每原段窗口调用原_nf_search_intervals；只有整窗best=None才进下一窗。
不要继续执行旧的‘正向[ref,end]、反向[first,ref]’硬边界分支覆盖当前段窗口。
位置求值仍用原系数和原曲线帧，不做第二次总时长-frame镜像。
数学包络、方向同分和原Move求解保持；强制准备增加显式当前/目标虚轴行程检查。
