# 用户与权限模块设计

日期：2026-10-26
状态：已实现（分支 feat/user-permissions，2026-10-26，未提交）

## 1. 目标与范围

- **用户跟着电脑走**：每台电脑有自己的用户、角色和权限，存在本机，不写进工程文件，不随工程导入 / 导出 / 另存，也不随多机协作同步。
- **按角色授权**：一个用户属于一个角色。「管理员」角色内置，拥有全部权限；管理员可以新建、修改、删除其他角色。
- **按权限显示 / 隐藏**：没有权限的入口和按钮直接不显示。
- **偏好跟着用户走**：显示单位存在用户身上，谁登录用谁的。系统设置新增「用户」页，显示当前用户信息和偏好设置。

本期不做：密码复杂度 / 过期 / 失败锁定 / 会话超时（演示稿的「安全策略」页先去掉）；给单个用户单独加减权限（演示稿的「自定义权限」）；一人多角色；按工程 / 设备 / 章节授权。

## 2. 权限设计原则

1. **权限点 = 一个开关**，按功能板块分组，每个开关对应界面上具体的入口和按钮。不沿用演示稿的「查看 / 操作 / 配置 / 管理」四级矩阵，那四级对应不到具体按钮（比如「动作编辑 · 配置」指什么说不清）。
2. **让设备停下来的操作永远不受限**：急停、任务卡 / 推子的停止和暂停、锁屏上的急停，任何登录用户都能用。**让设备动起来的操作都要权限**（GO、点动、回原、走平、继续、重新……）。
3. **基础能力人人都有**，不出现在勾选列表里（见 3.7）。
4. **隐藏规则**：导航、标签页、菜单项、按钮这类"点了就执行"的元素，没有权限就隐藏；推子、开关、表单输入这类本身在显示状态的控件，没有权限时只读显示（看得到值，改不了）。
5. **隐藏不等于拦住**：同一个操作的快捷键、拖放、右键菜单、本机 AI 写入，按同一个权限点拦截，不能绕过。

### 3.1 控制（演出运行）

## 5. 角色与用户规则

**角色**

- 名称在本机唯一；可填说明。
- 「管理员」角色不能改名、改权限、删除。
- 新建角色可以「从现有角色复制」权限。
- 有用户在用的角色不能删，提示先把这些用户改到别的角色。
- 勾选联动：勾上某个板块的编辑类权限，自动勾上该板块的「进入」；取消「进入」，同时取消该板块的编辑类权限。

**用户**

- 用户名：登录用，本机唯一，不区分大小写，创建后不能改。
- 显示名：界面和操作日志里显示，本机唯一。
- 角色、启用 / 停用、创建时间、上次登录时间。
- 必须至少留一个启用的管理员：最后一个管理员不能删除、停用或改成别的角色；管理员不能删除自己。
- 管理员可以重置任何人的密码；每个人可以在「用户」页改自己的密码（要输旧密码）。
- 密码至少 4 位，不做复杂度要求。
- 一台电脑同一时间只有一个登录用户。管理员改了别的用户，对方下次登录生效。

## 6. 登录、切换与操作人

- 启动后必须登录（沿用现有登录页，改成查本机用户）。停用的账号登录提示「账号已停用」。
- **切换用户**：在控制台上弹出登录框，控制台不关、设备不受影响，急停一直可点；登录成功后界面按新用户的权限刷新，「取消」回到原用户。当前所在页面或标签新用户没有权限时，回到「控制」页。
- **退出登录**（2026-10-26 按长时间运行要求修改）：在控制台里退出不再回登录页，而是结束会话、原地弹出同样的登录框（不能取消），控制台不卸载。登录页只在软件启动、还没打开工程时出现。
- 不做自动登出（演出中被登出有风险）。
- **不做自动登录**（2026-10-27 确认）：只在本机记住上次登录的用户名（不含密码），登录页和退出后的原地登录框预填它、光标直接在密码框；「切换用户」不预填（是换别人登录）。理由：自动登录会让下一个开机的人直接拿到上一个人的权限，操作日志也会记错人；软件一直开着时本来就不用重新登录。
- 登录 / 切换后把当前用户的显示名交给 C++（`csocketApi.configure({ user })`），操作日志的「操作人」从此有值。退出登录时清空。
- 新建工程的「作者」填当前用户的显示名（现在写死「当前用户」）。

## 7. 「用户」页与偏好设置

系统设置弹窗人人能打开，左侧只显示有权限的分类。新增第一项「用户」，打开时默认停在这里：

- **基本信息**：头像（显示名首字）、显示名、用户名、角色、本次登录时间。
- **操作**：修改密码、切换用户、退出登录。
- **偏好设置**：显示单位（米 / 厘米 / 毫米 / 英寸），从「界面设置」移过来。新用户默认毫米。
- **我的权限**：只读列出当前角色有哪些权限，方便知道某个按钮为什么不见了。

只有显示单位跟着用户走。「界面设置」留下语言、主题、时间格式三项（现在都是占位），属于本机设置，归 `system.settings`。

显示单位登录时按用户的偏好生效，改了立即生效（去掉现在的「重启后生效」）。现在单位在启动时冻结一次，切换用户不重启，所以要改成随登录用户变化，实现时逐个检查单位的使用方（3D 标签、遥测、数值输入框正在编辑的草稿）。

## 8. 存储与安全

- 主进程管理用户数据，文件放 Electron 用户数据目录（Windows 一般是 `%APPDATA%\yzapp\users.json`）。不放安装目录：安装包配置了卸载不删用户数据目录（`deleteAppDataOnUninstall: false`），升级、重装后用户还在。
- 密码只存加盐哈希（Node 自带 scrypt），哈希不出主进程。
- 渲染进程通过 IPC 调：登录、退出、当前会话、改密码、用户和角色的增删改。用户和角色的增删改在主进程里再检查一次当前会话是不是管理员。
- 写文件先写临时文件再改名，防止断电写坏。
- **首次使用**：`users.json` 不存在时自动建好内置管理员账号 `admin`（默认密码 `admin123`，沿用现在演示账号的密码，写进说明书）和三个预设角色，不预建技术员、操作员账号。用默认密码登录后先弹「修改密码」，改完才能继续，新密码不能和默认密码相同。
- 管理员给别人重置密码后，那个用户下次登录同样要先改密码。
- 忘记管理员密码：删掉 `users.json` 重启，回到 `admin` / 默认密码（写进说明书；能碰到电脑文件系统的人本来就能做到）。

## 8.1 长时间稳定运行

软件要连续开机、长时间运行（用户 2026-10-26 提出），用户与权限不能成为不稳定的来源：

- **登录相关操作不卸载控制台**：切换用户、退出登录都是控制台上的原地登录框，3D 引擎、设备连接、任务卡状态、未保存的动作草稿都保留。反复登录退出不会反复销毁、重建 3D 引擎（WebGL 资源）。
- **不打断设备**：换人、权限变化只改按钮显示，不发任何设备指令；运行中的任务继续；停止、暂停、急停永远可用。因权限被隐藏的控件卸载时，按住的点动先发停止（调试页点动按钮补上卸载时停止）。
- **登录框打开时拦住背后的快捷键**，避免在登录框上打字触发控制台快捷键。
- **没有定时器、轮询、自动登出**：会话在主进程内存里，渲染进程崩溃重载后仍是登录状态，控制台直接恢复；软件退出会话才结束。
- **不增加运行开销**：权限判断是集合查找，只在渲染和点击时做；权限数据只在登录、切换、改偏好时变化，不碰遥测等高频刷新。
- **磁盘问题不挡登录**：文件只在登录和管理操作时写（先写临时文件、落盘后改名）。记录上次登录时间写盘失败只记日志；改密码必须落盘成功才算成功；文件损坏先备份再恢复成初始状态，启动不卡住。
- 单位切换走 3D 引擎已有的设置接口刷新标签，不重建场景。

## 9. 已确认的选项（2026-10-26）

| 问题 | 结论 | 没选的方案 |
|---|---|---|
| 搭建 / 动作页分不分「进入」和「编辑」 | **分两档**：没有编辑权限能进去看，页面只读 | 不分：能进就能改，看不了就整页隐藏 |
| 首次使用怎么产生管理员 | **内置 `admin` + 默认密码**，首次登录强制改密（第 8 节） | 首次启动显示「创建管理员」页面 |

| 切换用户的方式 | **原地切换**：控制台不关，设备不受影响（第 6 节） | 只能退出登录、回到登录页 |
| 长时间稳定运行 | **退出登录也改成原地登录框**，其余见 8.1 | — |

## 10. 实现要点（已按此实现）

- 权限注册表在 `shared/auth/permissions.ts`（主进程建预设角色、校验角色权限也要用，所以放 shared）：板块、权限点、说明、依赖（编辑类依赖「进入」）、预设角色。
- 主进程 `electron/main/auth/`：`service.ts`（规则全在这里，操作排队执行）、`storage.ts`（原子写 + 落盘，坏文件备份）、`password.ts`（scrypt）、`index.ts`（IPC，`YZ_USERS_FILE` 可覆盖文件位置）。会话变化时把显示名交给 C++（`electron/main/index.ts`）。
- 首次登录 / 重置后改密码是两步：`login` 返回 `MUST_CHANGE_PASSWORD`，再用 `loginWithNewPassword` 改完才建立会话；新密码先落盘再登录。
- 管理员新建用户、重置密码时有「首次 / 下次登录需修改密码」勾选，默认勾上（共用账号时可以不勾）。
- 渲染进程：`src/app/auth/auth-provider.tsx` 镜像主进程会话（读回之前不渲染界面）；`src/app/auth/permissions.tsx` 提供 `usePermissions()`、`<Can>`；没有 AuthProvider 的单元测试按全部权限处理，测试里用 `TestPermissionsProvider` 指定权限。
- 只读：`src/app/components/ics/read-only-scope.tsx`（fieldset disabled + 上下文），数值输入框、滑块读上下文；折叠面板标题和页签改成不受 fieldset 影响的 `role=button` / `role=tab`，只读时仍能展开、切换。
- 动作编辑的总闸在 `action-builder-context.tsx`：`updateSelectedSequence`、`commitMotionProjection`（改序列看动作编辑，只改节目看节目编排）、编辑器撤销 / 重做。
